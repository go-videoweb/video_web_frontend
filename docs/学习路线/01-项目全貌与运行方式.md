# 01 项目全貌与运行方式

状态：项目讲解已补充。目标是先能运行和定位，不要求先学完 React。

## 先体验

从仓库根运行 `pnpm dev`，打开 http://127.0.0.1:5173/?mode=demo 。依次进入发现、观看、投稿、账户设置。退出“演示环境”后，真实模式不会显示这些模拟视频。

终端 Ctrl+C 停止自己启动的 Vite；浏览器关掉不等于服务器停止。端口被占时使用 `pnpm dev --port 5174`，不要结束不认识的进程。

## 四个运行角色

浏览器运行 React，负责把数据变成界面。Vite 在开发时提供模块和热更新，也将 /api 转发给 Go；生产时它不在业务请求链上。Go 网关负责鉴权与 HTTP 业务入口。MySQL/Redis 等仅由后端访问，浏览器不知道数据库密码。

```text
开发：浏览器 :5173 -> Vite -> /api -> Go 网关 :8001
生产：浏览器 -> Nginx 静态文件 / 同域 /api -> Go 网关
演示：浏览器 -> MSW 拦截 /api；媒体读取本地 MPD/m4s
```

页面打开只证明前端可以加载。静态健康检查成功不能证明登录、邮件、DTM 或上传转码工作正常。

## 从入口读起

main 的 start 先判断是否演示，再启动 worker，最后 render。先启动 worker 可以避免首页请求早于模拟器就绪。真实模式根本不导入 handler，不以 catch 网络错误作为“自动演示”条件。

QueryClientProvider 让后代组件获得同一个缓存；RouterProvider 根据地址选择页面。Provider 可以先理解为给整棵组件树提供一种能力，不必先记住所有 Context 实现。

StrictMode 是开发检查，不是登录或安全机制；Effect 要能正确清理，不能假定只执行一次。

## 命令怎么选

- `pnpm dev`：修改源码，连接配置的真实网关。
- `pnpm dev:demo`：开发进程强制演示；需要真实模式时停止它再用 dev。
- `pnpm build`：类型检查后生成 dist，不会启动后端。
- `pnpm preview`：检查 dist，不能替代生产 API 代理。
- `pnpm test`：单元和组件测试，不连接业务数据库。

## 可选练习

只修改 index.html 的 title，刷新标签页确认变化，再运行 pnpm build。不要同时改路由、代理与业务 API。若标题变了但登录失败，分别查看页面资源与 /api 请求，而不是认为 React 没启动。
