## 用户信息如何共享

导航头像、详情作者、评论作者和个人页都使用 user 查询 key。更新昵称后失效 ['user',userId]，活跃界面会重新读取。不自己维护“导航昵称”和“评论昵称”两份长期状态。

当前查询要求登录。个人页显示资料与计数，不把全站视频按昵称过滤后当“该用户投稿”；后端没有投稿列表查询。只有本人页显示邮箱/生日是一层正常展示约束，不构成服务端隐私保障；接口是否越权仍需后端核对。

## 设置表单

昵称由 RHF/Zod 校验后单独提交；签名单独提交。密码修改成功清会话并要求重新登录，不将密码保存在缓存或草稿。邮箱验证码有 60 秒按钮冷却，但安全限流与验证仍属于后端。

设置两个选项在 /settings 内切换，不是两个独立后端操作集合。不同字段独立提交，避免把没有修改的旧数据一起覆盖。

## 头像

先选择本地图片并创建 Object URL 预览，再提交 avatar multipart。失败清预览；切换图片或组件卸载 revokeObjectURL，释放浏览器资源。

后端 avatarPath 可能是本机文件路径。publicImage 拒绝 Windows 盘符、javascript:、协议相对 URL，仅使用可访问站内/http(s) 地址，否则显示字母头像。预览上传成功不保证下次刷新能显示，真正持久展示需要后端安全头像 URL/读取接口。

## 为什么收藏、关注没有假页面

收藏夹创建不返回 ID，且没有查询列表/内容；前端无法可靠知道给哪个夹修改/删除/收藏。localStorage 造一份会把“看起来成功”与真实数据库脱节。

关注要 followListId，却没有默认列表发现，摘要还缺目标 userId。要求用户手填 ID 不能形成正常视频社区交互。API 适配保留以便补齐后接入，但导航不放死入口，不猜数据库 ID。

这不是 React 技术难题，而是契约缺数据。补齐后顺序应是：更新快照 -> 运行时模型 -> query/mutation -> 页面 -> 权限与回读测试，不能只加按钮。

## 可选练习

在演示修改昵称，观察顶栏与资料页是否刷新；切换账户安全查看表单，不输入真实密码。阅读头像清理 Effect，说明为什么依赖 previewUrl。

练习只调整签名最大显示宽度，检查长单词/长中文不挤出布局；不要为了撑满页面显示邮箱或生成假的个人视频。

## 自检

3. 收藏夹缺少创建 ID 时，前端为什么不能猜自增 ID？
4. 哪些资料在缓存失效后自动更新，哪些表单本地输入应该保留？
