## 为什么不能一个按钮全部假完成

创建元信息返回 videoId；文件和封面上传依赖这个 ID。当前网关可能先接受请求，再在 goroutine 中继续上传/转码。HTTP 成功只能说“已提交处理”，不能说“发布完成”，更不能用前端计时器画出 100% 转码。

```text
无 draft -> 创建元信息 -> 得 videoId -> 保存 draft
有 draft -> 上传视频/封面 -> 分别记录已提交
失败 -> 保留 ID 和另一已完成步骤，不重新创建
刷新 -> 读同用户 draft -> 重新选文件，继续同一个 ID
```

## 草稿是什么

draft 只保存 userId/videoId/title/videoSent/coverSent，存在 localStorage。不是服务端视频管理，也没有保存 File、密码或 token。schema 检查本地内容，坏数据忽略；保存失败提示保持页面打开。

文件输入不能在刷新后自动恢复原文件，这是浏览器安全边界。localStorage 按用户 ID 分隔；更换账号不应直接拿另一个用户 ID 投稿。演示/真实业务仍需使用不同身份，完整清理可以通过“开始新投稿”移除记录。

“开始新投稿”是放弃本地恢复记录，不会删除已创建的服务端视频。当前没有视频删除接口，操作前需要确认。不要把清本地缓存叫回滚。

## multipart 的关键

上传视频使用 file，封面使用 cover，头像另外是 avatar。FormData 自己设置 boundary；手写 Content-Type: multipart/form-data 会丢 boundary 导致服务端解码失败。

前端限制文件类型/大小是提前反馈，不是安全检查。后端还要独立限制内容、权限和资源路径。Vite、Ingress、Nginx、Go 的大小/超时限制也需要一致，某一层接受不代表整个链路接受。

## 两种失败

明确返回失败可以呈现说明；连接中断则可能已创建元信息，不能自动再创建。前端保留已知 ID，但若创建成功响应本身丢失，就没有可靠 ID 可恢复，必须核对后端结果。首版不宣称解决这个缺口。

提交文件后允许显式打开观看页检查，不轮询详情当处理进度，因为详情增加播放计数。准确完成/失败状态、断点续传、服务端幂等需要新增契约。

## 可选练习

演示创建元信息，提交视频后刷新，再上传封面。Network 里 metaInfo 应只有一次；E2E 已检查计数。不要用真实大视频反复测试未知处理结果。

阅读 save/readDraft，画出每步失败时已经存在的资源；比较“删除 localStorage”与“删除服务端视频”的差异。运行 pnpm test:e2e --project=desktop --grep "投稿"。
