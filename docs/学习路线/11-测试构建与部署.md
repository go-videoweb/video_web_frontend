## 不同检查回答不同问题

typecheck 检查类型，lint 检查代码规则，format:check 检查排版；它们都不会证明业务正确。Vitest 在 jsdom 中检查 UI 与请求，但 jsdom 不会真实解码视频。Playwright 启动真正浏览器，能验证点击、网络、画面与截图。

MSW 代替 Go 响应，因此 E2E 通过仍不能证明 Redis/DTM/邮件/ffmpeg 正常。媒体用实际 DASH 与 m4s，所以能证明当前浏览器确实播放了这段流，但不能推广到所有编码或 iOS。

## 先用小测试理解

读取 client.test 一个用例：准备假 fetch -> 调用 request -> 断言头或返回值。vi.stubGlobal 替换当前测试的 fetch，afterEach 恢复，不能把 mock 带进真实模式。

RTL 用可访问名称找字段与按钮，再 userEvent 输入/点击，观察错误或导航。不要把测试写成只断言某个内部 state，它不是用户行为契约。

E2E 对 360/768/1440 做同一核心流程。宽度不溢出只是一项检查；还要查看截图、图片 naturalWidth 和 video 像素。全页截图中的懒加载图片要先进入视口，不能把还没请求误判成坏图。

## 常用命令

```powershell
pnpm api:check
pnpm typecheck
pnpm lint
pnpm format:check
pnpm exec vitest run src/lib/api/client.test.ts
pnpm test
pnpm build
pnpm test:e2e --project=desktop
```

测试失败先看第一条有因果意义的错误，不逐个改快照把红色变绿。未知错误不要一律 catch 并返回默认成功。

## 构建与部署

build 生成 dist，带 hash 的 JS/CSS 可长期缓存；HTML 不长期缓存才能引用新版本。路由/播放器懒加载减少首页首批代码，但不代表总包体减少。dash.js 仍有大 chunk 警告，已记录，没有通过提高阈值假装优化。

Dockerfile 是独立前端构建，不需要兄弟后端源码。Nginx 提供静态文件并代理 /api；SPA 刷新需要回退，API 404 不能回退 HTML。k3s 清单只管前端，网关地址/域名/证书/镜像需要部署者核对。

pnpm preview 不是生产代理。前端 dist 也不能证明镜像已构建，kubectl YAML 能解析不等于集群资源成功。

## 可选练习

修改一个纯函数断言让它失败，读输出后恢复，再运行目标测试。接着 build，看看 dist 路由 chunk 与 dash chunk，理解懒加载。不要把 dist、node_modules、trace 或本机 env 提交进 Git。

## 自检

- 编译通过为什么仍可能显示业务错误？
- 真实模式不回退演示数据为什么是重要验收点？
- /healthz 成功为什么不是全链路成功？
- 浏览器移动视口和真机 Safari 有什么不同？
