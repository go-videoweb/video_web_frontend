# 12 独立修改与问题排查

状态：项目讲解已补充。目标是形成可重复的小步修改方法，不要求你先独立重写网站。

## 先选一条最短路径

只想做简历演示，先会运行、切换模式、说明能力边界即可。准备亲自改动时，选一个小目标，不同时补 JS、React、测试、部署全部知识。

| 修改目标     | 起点                    | 验证                 |
| ------------ | ----------------------- | -------------------- |
| 卡片显示顺序 | videos/video-card.tsx   | 类型、发现页三种宽度 |
| 昵称校验提示 | users/settings-page.tsx | 表单空值/过长/提交   |
| 分类配置     | lib/config.ts、env      | URL 与真实 class 值  |
| 评论错误提示 | comments/comments.tsx   | 失败保留输入         |
| 新接口字段   | contracts、api、models  | 契约检查与边界测试   |
| 媒体错误     | player/player.tsx       | MPD/分片/可见画面    |

完整路径从 [架构说明](../架构与接手.md) 和 [大纲](大纲.md) 跳转。

## 一次改动的六步

1. 写一句可以观察的目标，例如“长标题不挤出手机宽度”。
2. 在演示复现，记录 URL、窗口宽度和当前截图。
3. 找数据入口、组件与样式，只选相关文件。
4. 先小改，再做最窄检查，不顺便重构其他功能。
5. 执行类型/lint/相关测试，必要时补回归。
6. 说明改了什么、实际检查了什么、还有哪些未验证。

“按钮出现”不是目标完成；它的 loading/error/成功与刷新后的状态都可能影响验收。

## 按层排错

页面完全空白：先看资源加载与控制台，再看路由，不先怀疑数据库。

数据没有：看 Network 是否真的发送、地址/模式/两种头/业务体；HTTP 200 也要检查业务码。不要为了排错打印 token。

标题有但画面无：查 MPD、相对分片、编码与 MSE。给 video 加宽不会修好分片 404。

刚更新没变化：看失效的 query key、是否当前用户、是否把服务端数据复制进 stale state。不要整站 invalidate 强行刷新，因为详情有副作用。

刷新后丢登录：分清 sessionStorage 标签页生命周期、业务失效与退出；不能自动拿另一用户会话补上。

提交后结果未知：停止自动重试，保留 ID/输入，查服务端日志或专用查询；前端不能根据超时断言回滚成功。

## 怎样让 AI 协助而不失去理解

请求可以写成：“只修改某文件的某行为；先说明输入、输出和副作用；不要动后端；补一个覆盖失败路径的测试；报告真实执行结果。”阅读 AI 改动时先看 diff 和测试，不从依赖目录开始读。

代码解释优先问“为什么在这一层”“失败如何处理”“谁负责清理”，而不是要求每行注释。你能画出输入 -> API -> 状态 -> 界面，通常就已足够做下一步局部修改。

## 可选练习梯度

- 入门：改一条可见文案，检查没有溢出。
- 小步：为一个输入增加校验与组件测试。
- 中等：为已存在字段增加展示与 schema 默认值测试。
- 进阶：后端明确补齐收藏 ID/查询后，按 api -> model -> query -> 页面闭环实现，不靠本地假数据。

练习不设硬性天数，也不是这次交付的前置条件。只在需要修改某功能时学对应章节，其余内容可后读。

## 最后自检

给自己解释一条评论如何从 textarea 到后端，再回来更新列表。能指出重试、身份和缓存三个风险，就可以开始安全的小修改；还不清楚时回到第 04/05/08 章，不必重学整套课程。
