# 章节编写模板

本文件约定详细章节的格式，不代表任何具体功能已经实现。初期提纲可以先列章节边界，展开时按以下结构补全。

## 章节状态

记录对应功能、核对代码的日期/版本、前置章节与尚未完成的内容。明确这是计划、代码讲解还是已验证操作。

## 1. 本章目标

使用“能解释某条流程”“能定位某个文件”“能完成某项修改”等可观察目标。

## 2. 从功能体验开始

描述入口、用户操作、成功结果和主要失败情况；有实际页面后再添加截图，不用虚构界面代替。

## 3. 必要知识

解释本章需要的少量语法或概念，链接已有基础章。标注现在需要理解与以后可以深挖的内容。

## 4. 代码阅读地图

| 阅读顺序         | 实际文件/符号          | 负责什么 | 阅读时要回答的问题 |
| ---------------- | ---------------------- | -------- | ------------------ |
| 待代码实现后补充 | 不填写不存在的源码链接 | 写清边界 | 避免只罗列文件名   |

## 5. 跟踪一条完整流程

从用户事件出发，连接组件、状态、请求、响应和渲染。必要时使用简短 Mermaid 图，并补充失败分支与清理行为。

## 6. 为什么这样设计

说明组件边界、状态归属、工具职责和重要取舍。区分通用原则与当前项目选择，不将个人偏好写成唯一正确方案。

## 7. 关键代码讲解

选取实际源码片段，附核对过的文件链接。说明输入、输出、关键语法、错误条件和副作用；完整源码仍留在工程中。

## 8. 动手验证

提供一个可选的小修改，写清允许修改的范围、可观察结果、必要验证以及恢复办法。提示与参考解答分开，不要求读者重写整项功能。

## 9. 常见误区与排查

按“现象 -> 可能原因 -> 查看位置 -> 如何验证”组织，优先使用实际遇到的案例。

## 10. 自检与延伸

提供少量理解问题和官方延伸资料，不以记忆 API 名称为目标。记录本章相关测试是否运行，模拟与真实环境结果分别说明。
